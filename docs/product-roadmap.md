# FolioTrace 产品方向与功能优先级

## 产品中心：可回溯的研究过程

研究问题 → 材料范围 → 阅读与校订 → 判断与反证 → 人工复核 → 带出处的研究产物。AI 帮助寻找、比较和组织线索；研究者能够检查每一个判断的来处。保留竞争解释、不确定性和负面结果，不把流畅表达、材料数量或模型信心等同于论证成立。

## 本次已实现

| 研究环节 | 可用能力                                                                                         | 实现边界                                                                  |
| -------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------- |
| 收集出处 | 完整书目字段；CSL JSON、BibTeX、RIS 预览导入、去重与导出；Zotero 个人库读取                      | Zotero 不导入附件、不写回、不持续同步；key 不在服务端保存                 |
| 引用材料 | Chicago / APA 参考书目、Chicago 定位脚注；作者、版次、纪年、馆藏、档号与权限                     | 研究者补齐未知字段；文件页序与原书页码明确区分，未做自动文稿排版          |
| 阅读校订 | PDF / 照片逐页预览、原件区域框选、引文文字区间、固定旧版本导航                                   | 区域由研究者选取；没有自动行级 OCR 对齐或字级置信度                       |
| 保护工作 | 按账户和项目隔离的本机校订 / 笔记草稿；刷新后恢复；逐行 diff；恢复为新版本                       | 本机草稿不是跨设备同步或备份；清理浏览器数据会移除草稿                    |
| 复核判断 | 问题、判断、竞争解释、下一步行动；支持 / 质疑 / 背景证据；引文页面变更后人工复核                 | 人工复核状态不代表结论已被证明；不自动改写旧引文                          |
| 追溯关系 | 转引、转载、翻译、共同来源；关系依据与确认程度                                                   | 人工记录，尚无自动谱系推断、实体消歧或复杂图布局                          |
| 说明检索 | 检索词、范围、日期、命中数、无命中、无法访问与不完整覆盖日志                                     | 人工检索日志；尚无跨材料全文搜索或自动判断史料空白                        |
| 后台分析 | Queues 消费、D1 检查点、固定输入、显式模型、费用预留、暂停 / 继续 / 取消、人工重试、收件箱       | 当前为一次材料分析；只在调用前允许暂停 / 取消；调用后不确定结果不自动重试 |
| 持续关注 | Cron 每 15 分钟检查到期关注；每日 / 每周 Crossref 最新 DOI 元数据、内容去重、失败状态、待审收件箱 | 每次仅前 20 条，覆盖不完整；不涵盖全网或档案馆；不发送关注邮件            |

现有能力继续保留：私人账户、R2 原件、不可变资料和笔记版本、多厂商 BYOK、当前页 OCR、项目 JSON 导出，以及 Material 3 风格工作台。当前页 OCR 仍为即时调用；后台预算不覆盖它。费用按用户声明的模型费率估算，实际账单以厂商为准。

## 下一阶段：可靠地接入真实研究

1. **只读云盘导入**：Google Drive OAuth，用户选择范围；文件级进度、去重、可恢复失败、来源链接；首先导入，再考虑持续同步。
2. **全文检索**：关键词、异体字和别名；结果显示原文片段、版本和页码；按年代、作者、馆藏与语言过滤。语义检索以后加入，并允许与精确命中分开检查。
3. **完整项目迁移**：原件、全部元数据、不可变版本与关系打包；校验清单；可验证恢复。现有 JSON 导出不包含附件二进制。
4. **OCR 质量工作台**：可取消的批处理、页面级重试、引擎记录、人工校订量；评估一种明确的史料和语言后再扩展。字形、缺字、原始排版与译文分别保存。
5. **研究写作**：从已复核证据形成提纲；检查缺少出处、引文不匹配、旧版本和竞争解释遗漏；带脚注的文稿导出。

先选择一组授权史料跑完一条真实路径，例如“导入中文报刊 → 校订关键段落 → 比较同一事件 → 核查引用链 → 导出证据与书目”。已实现的功能不等于完成真实账号与生产联调。

## 后续扩展

- 人物、地点、机构与事件的候选关联；研究者确认实体合并，保留依据和撤销路径。
- 约年、日期区间、不同历法与历史地名；在时间线和地图上表达不确定性，不强迫虚假的精度。
- 团队成员权限、评论、待审修改与采纳，公共分享单独授权。
- 多步骤 agent 研究：可检查的计划、每步材料范围、预算、检查点、人工复核关口；扩展数据源适配器与覆盖报告。
- 大规模语料统计和比较：附出处、抽样误差、漏检范围、模型版本和人工修订。
- 根据试用反馈决定离线 PWA / 本地伴随程序与机构登录，先验证 SaaS 研究闭环。

## Cloudflare 实现约定

Workers 承载网站和后台消费者，D1 保存关系、版本与检查点，R2 保存原件，Queues 投递分析任务，Cron Triggers 调度到期工作，Better Auth 使用 D1。当前没有使用 Workflows；如果研究扩展到多步骤和人工暂停，再评估引入。大量正文后续迁往 R2，索引和关系留 D1；容量、吞吐和成本以实际负载测量为依据。

BYOK 继续支持用户选择外部 LLM；不静默跨厂商降级。后台预留预算不能替代厂商账单上限。外部调用已开始但结果未知时保留费用预留，人工重试会创建新的任务和费用预留。

## 验证研究加速

使用相同授权材料与明确任务，对比原流程和 FolioTrace：找到可核查出处的时间、引文与页码正确率、OCR 校订量、重要材料漏检率、错误推断复核成本、每个被采纳发现的调用费用。保留负面结果和无法判断的项目。加速以出处与复核质量可接受为前提。

## 视觉约定

延续 Material 3 的 surface、primary 和 tonal container 颜色角色，复用 Base UI / shadcn 的交互与无障碍能力。Roboto 与系统中文字体，研究文本保留衬线排版；按钮、选中态、焦点、弹窗、空状态、版本差异和移动布局使用共享样式。支持浅色、深色和跟随系统；原始扫描件不做反色。最新验证见 [外观与方法验证](method-validation-and-appearance.md)。
