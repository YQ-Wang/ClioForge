# Import and writing UI verification

The writing import disclosure used a flex layout that crowded its summary,
replacement warning and native browser file control into one row. It now keeps
the controls inside a collapsible block with one explanatory paragraph and a
localized selection button. File selection in replay, IIIF manifests and backup
restore uses the same component. Selected filenames wrap; cancelled selections
do not clear the previous selection; input values reset so the same file can be
selected again.

Chrome validation used a local synthetic note, not a production research draft:

- Collapsed import hides its controls; Enter expands and collapses the summary.
- An invalid JSON document preserves the original draft and displays an error.
- A subsequent valid ClioForge document replaces the draft and clears that error.
- Undo restores the original text. The trial note was left as a local draft.
- Desktop Chinese/light and 390-pixel English/dark layouts were visually
  inspected. At 390 pixels the dialog width was 358 pixels and the page's scroll
  width remained 390 pixels. Native file inputs were not visibly exposed.
- The narrow-screen footer places find and export controls side by side, and
  long English disclosure text has space reserved for its indicator.
- The project-restore dialog exposes the matching localized backup button and
  leaves the restore action disabled until a valid backup is selected.

Browser viewport, appearance and language settings were restored after testing.
This is a focused interface iteration, not a new end-to-end certification of
archive retrieval, backup restoration or every platform feature.
