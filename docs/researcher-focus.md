# Canwoo：以实际研究任务决定产品

当前目标是帮助一个研究者或小组更快找到、阅读、比较并核查材料，最终留下可追溯的研究笔记。是否有效，要看完成这些任务所用的总时间、核查负担和成果质量。任务数量、Agent 数量、模型输出长度都不是研究进展的替代指标。

## 有依据的起点与尚未证实的假设

- **寻找可比较的历史材料确实是研究任务。** Aeneas 的研究由历史学者参与评估，检索平行铭文被当作进一步研究的起点，而非最终解释。牛津的介绍也说明史家如何利用措辞、公式和出处寻找平行材料。这支持“检索—对读—回到原件”的产品方向，不能证明 Canwoo 已具有 Aeneas 的模型能力或同样的效果。[论文](https://www.nature.com/articles/s41586-025-09292-5)，[牛津古典学系](https://classics.web.ox.ac.uk/article/aeneas-an-ai-model-for-restoring-and-contextualizing-latin-inscriptions)
- **共享材料和协作整理已有明确使用场景。** Zotero Groups 支持同事在项目中共享文献和私有资料库。Canwoo 要围绕这些协作行为补齐邀请、权限和撤销访问，不另外创造复杂的组织结构。[Zotero Groups](https://www.zotero.org/support/groups)
- **Discovery Loop 值得借鉴的是可衡量的循环。** 它公开提出先聚焦机器学习，并作为自己的首个客户，再向其他领域扩展。Canwoo 也应先验证少数研究任务，而不是预先声称适用于所有人文学科。[Discovery Loop](https://www.discoveryloop.com/)
- **Prove2Me 的形式化验收不能原样移植到历史解释。** 它的公开任务包含机器检查的数学重建。Canwoo 可以自动检查引文是否存在、页码是否匹配和结果是否依赖正确版本；材料是否支持某个历史解释仍需领域判断。[Prove2Me](https://beta.prove2.me/)

以上属于问题方向的外部证据。Canwoo 的可用性、付费意愿和真实提效仍需研究者试用验证。

## 本轮交付围绕的任务

1. 负责人邀请合作者共同整理一批材料。邀请绑定邮箱，接受前无权读取项目。仅负责人调整权限、撤销邀请和移除成员；材料、笔记与已留下的核查记录保留。
2. 研究者输入一个名字、地点或词句，在项目概览直接找原文，点击结果进入对应资料版本与页码。这一步无需创建研究计划或调用模型。
3. 多人阅读同一批固定版本，协作者保存工作笔记，复核者检查出处和解释边界。需要重复多步处理时，才使用已有研究计划。

协作采用一个项目、一份成员列表和三种清楚的权限：仅阅读、协作编辑、协作并复核。创建邀请后复制链接发给对方，对方也能在登录后的“我的研究”看到邀请。当前不自动发送邀请邮件。成员各自的模型密钥和 Google 授权不共享。

## 已完成的验证

2026-09-05，本地 40 项回归全部通过，包括邮箱绑定、未注册者受邀、明确接受、撤销/接受竞争、邀请更新与重放、成员权限变更、移除后资料隔离、保留协作笔记，以及降为仅阅读后排队模型任务不再发起调用。

公开数据测试使用官方 LED JSON 前 40 条记录，保留原文、出处和许可。模拟负责人、协作者、复核者三个账户，完成导入、寻找 `Dis Manibus`、比较措辞、词语统计、引文检查、共同笔记和复核。检索定位 `HD010014 · Roma`，两个成果经过复核，计划达到 completed；随后校订原文会使依赖旧版本的结果进入待重新处理状态。记录在 `work/research-collaboration-evaluation.json`，可运行 `npm test` 复现。

这是软件集成验证。40 条便利样本不代表罗马铭文总体；当前措辞比较使用词汇基线，未接入 Aeneas 模型。测试中的人物操作和复核意见由脚本模拟，**没有测得学者节省的时间，也没有证明历史解释正确**。本轮未调用收费模型。

## 确认真正提效的下一步

先邀请少量研究者，用她已经在做的题目进行任务试用。请她带一批可以使用的材料，并说明原本如何完成任务。第一轮只观察三个任务：找到若干相关原文、比较两份材料的相同与差异、把带出处的笔记交给合作者核查。

用内容相当的任务交替比较原工具和 Canwoo，避免第二次做同一道题的熟悉效应。计入准备、上传、阅读、纠错、核查和导出时间。记录引用错误、漏检的已知材料、实际使用的研究线索、需要求助的步骤，以及是否愿意继续用。由学者事先给出相关材料与可接受成果的判断标准。

初步产品门槛是：在不降低引用准确性和核查质量的前提下，多位试用者反复获得净时间收益。30% 的总时间减少可以作为试用前约定的目标，不能当作现有成绩。找不到稳定收益的功能应修改或删除；领域不同的结果单独记录。

## 暂不扩大的范围

本轮不增加组织层级、自定义权限引擎、通用 Agent 市场、自动发表结论或复杂实时协同编辑系统。大规模自主研究、实体图谱、批量 OCR 和其它路线图项目是否优先，应由试用暴露的具体瓶颈决定。真实研究规模扩大前，先补齐可靠导入、成本边界、备份与恢复这些会直接影响研究工作的基础能力。
